> 制定日期：2026-09-30。基准仓库：`FSA_HLS`，分支 `fsa_split_D`。

> （`./run_hls.sh fsa_stream_split_d` 与 `FSA_SPLIT_D_PE_DIM=16 FSA_SPLIT_D_HEAD_DIM=128 ./run_hls.sh fsa_stream_split_d`）；

## 1. 总目标与验收标准

### 1.1 最终目标

参数化 `D×D` Split-D 顶层 `fsa_stream_split_d` 在 Vitis HLS 2024.2 上同时满足：

1. **数据正确**：4×4/16 与 16×16/128 两档的 CSim、CSynth、RTL CoSim 全部通过；全部用例在 0.03 容差内；无 deadlock、无 `Bad TV file`、C post-check 通过。
2. **硬件结构正确**：只有一套 `D×D` PE 阵列与每列一条 Accumulator 通路；不得为任何阶段复制阵列；DSP/BRAM/LUT/FF 与结构相符。
3. **时序通过**：器件 `xcvu37p_CIV-fsvh2892-2-e`、时钟 10ns、uncertainty 2.7ns 不变；HLS 估算周期 **≤ 7.300ns**。
4. **吞吐达标**：默认档 QK/ROW_SUM 循环 II=5、PWL/PV 循环 II=1；16×16 档达到同类目标或以用户新确认的口径为准。

### 1.2 硬约束（不得违反）

- 不修改 `FSA-main`；不改动生产顶层 `fsa_stream` 的行为；四个 64-bit AXI master bundle 与 AXI-Lite 控制接口不变。
- 不改阵列规模、器件、时钟、uncertainty、数据位宽来"通过"验收。
- 只允许一套物理 PE 阵列；禁止用复制阵列/Accumulator/关闭流水/虚假依赖声明换吞吐。
- 服务器测试只用仓库自带入口，禁止自定义测试脚本、wrapper、替代 Tcl、临时 testbench；CoSim 墙钟门槛 15–45 分钟正常、45–60 分钟警告、>60 分钟中断判超时。
- 每轮改动必须先在本地做结构检查，再推送精确 commit，由远端拉取后测试。

### 1.3 当前基线（实测，2026-09-30）

| 项目 | 4×4/16 | 16×16/128 |
|---|---|---|
| 数据（CSim/CSynth/RTL CoSim） | PASS / PASS / **9/9 PASS** | PASS / PASS / **7/7 PASS** |
| 顶层估算周期 | 需复测（上一通过点 **7.300ns**） | **7.934ns**（超预算） |
| 资源 | DSP **40**、FF 31486、LUT 125477、BRAM 8 | DSP **160**、FF 164470、LUT **545729**、BRAM 8 |
| QK / ROW_SUM 循环 II | 5 / 5 ✓ | **8 / 8** ✗（目标 5） |
| PWL / PV 循环 II | 1 / 1 ✓ | **5 / 5** ✗（目标 1） |
| `runPeArray` | latency 7、Final II 1 | latency 7、Final II 5 |
| `peBankMacUnit` | latency 3、Final II 1 | latency 3、Final II 1 |
| 每拍有效 MAC（推算） | 16 | **32 ~ 51**（目标 256） |

**基线 commit**：`174faa6` 之后的 `2a5a140`（= `caedc93` 去掉被证伪的强制时延 pragma）为"数据全对、仅时序与 II 未达标"的状态。

### 1.4 根因结论（已用证据钉死）

1. **`SCHED 204-65`（16×16 无法流水）的成因**是"bank 循环带 `UNROLL`"导致所有 bank 又被合成一个巨型单拍体；**去掉 `UNROLL` 后即解除**，综合时间从 ≥100 分钟降到 25–27 分钟。
2. **数值错误**来自 `runPeArray` 内跨 bank 迭代**共享的 `computed` 中间数组**（官方文档：未声明依赖时工具按"存在跨迭代依赖"以更大 II 保守调度）；改为每 bank 直接写自己的结果行后，16×16 数值全部通过。
3. **时序差距（+0.59~0.63ns）**来自 **rolled bank 循环**：`result[row][col]` 的写回索引随循环变量变化，路径上多了选择逻辑。对照实验：单 bank + 独立 `stagePeArrayResult` 寄存级的 `cf11987` 为 **7.300ns**；rolled 形状为 7.893/7.934ns；再加 `LATENCY min=1 max=1` 恶化到 **20.851ns**。
4. **II 未达标的官方原因**（Vitis 原文）：
   - `HLS 200-880`：`operand_c` 存在**真实**载运依赖（store@182 → load@186，distance=1），不是假依赖；
   - `HLS 200-875`：循环体内 `runPeArray` 调用延迟 8 拍，与 II=5 不兼容。
5. **效率根因**：当前形态是"每拍组合式重建整个阵列"（全分区 + 控制器广播/聚集），而参考设计（ASICON 2025 的 16×16 SA、spcl/gemm_hls、AutoSA、官方 systolic_array 示例）是"权重驻留 + 值沿邻居脉动"，每 PE 每拍一次寄存器到寄存器的 MAC，因此 II=1 是自然结果。**我们的 `peBankMacUnit` 已经证明：单拍 MAC 在 100MHz 下做得到（latency 3、Final II = 1），是外层控制结构把它拖住。**

## 3. P0：冻结 4×4 基线并固化证据

### 3.1 修改方法

不改代码。仅确认并落档：

1. 在**正式默认**参数下重跑一次 4×4（确认 `PE_BANK_ROWS = PE_DIM<=4 ? PE_DIM : 1` 与 `PE_ARRAY_II = PE_DIM<=4 ? 1 : 5` 的自适应选择没有引入回退）。
2. 把本轮全部对照实验（`cf11987` / `3a92f73` / `caedc93` / `9a6a100`）的数据、机理与结论写入 `PROJECT_CONTEXT.md`（已完成 `#15.00`）。
3. 记录 4×4 的 II 与延迟基线，作为后续所有阶段的回退判据。

### 3.2 验收目标

| 判据 | 目标 |
|---|---|
| CSim / CSynth / RTL CoSim | 全部 PASS（CoSim 9/9 + C post-check） |
| 顶层估算周期 | **≤ 7.300ns** |
| 资源 | DSP 40、BRAM 8；LUT/FF 与当前量级相当（允许 ±5%） |
| 关键循环 II | QK/ROW_SUM = 5、PWL/PV = 1 |

### 3.3 退出条件

## 4. P1：消除载运依赖、让阵列间隔自洽（局部改法）

### 4.1 目的

在不改变阵列形态的前提下，把 16×16 的 II 与估算时序拉回目标。这是**风险最低、收益有限**的一步，用于判断"是否必须做 P3"。

### 4.2 修改方法

**改动 A：消除 `operand_c` 的载运依赖。**

现状：QK 每 lane 循环内先把所有 PE 的 `score_acc` 写入共享数组 `operand_c`（controller.cpp:182），再由 `runPeArray` 从该数组读（:186），构成 distance=1 的真实 RAW。

改法（择一，按优先级）：
1. 让 `runPeArray` 的输入不再包含"下一次的累加值"：把累加交给 PE 本地状态，阵列只接受操作数 `operand_b`，返回值由调用方直接 `+=` 到 `pe[][].score_acc`；
2. 若必须保留三操作数接口，则把 `operand_c` 的写入与读取搬到**同一**流水级（写成 `computed` 后再统一提交），避免跨迭代读写同一元素；
3. 把 lane 循环的累加改到 block 级别一次完成（`DIM_BLOCKS` 轮、每轮 D 个特征），减少跨迭代状态更新次数。

**改动 B：让 `PE_ARRAY_II` 与函数实际延迟自洽。**

现状：16×16 时 `PE_ARRAY_II = 5`，但 `runPeArray` 实际迭代延迟 8 拍，触发 `HLS 200-875`。

改法：把 16×16 的阵列间隔设为**实测延迟**（先取 8，若改动 A 后再降到 5 更好），或改用 `PIPELINE` + `LATENCY` 组合，让工具按真实延迟调度；不得用 `LATENCY min=1 max=1` 强行压（已证伪，恶化到 20.851ns）。

**改动 C（可选，若 A/B 后仍差时序）：把寄存级做成独立非内联函数。**

`cf11987` 的 7.300ns 来自 `stagePeArrayResult` 这一"模块边界寄存级"（`INLINE off` + `PIPELINE II=1` + `LATENCY min=1 max=1`）。把它按 bank 切片重新引入 rolled 形状，使 `result` 的写回索引在一个独立流水级里成为常量，消除 rolled 带来的选择逻辑。

### 4.3 验收目标

| 判据 | 目标 |
|---|---|
| 16×16 CSim / CSynth / RTL CoSim | 全部 PASS（7/7 + C post-check） |
| 16×16 QK / ROW_SUM II | **5 / 5** |
| 16×16 PWL / PV II | **1 / 1** |
| 16×16 顶层估算周期 | **≤ 7.300ns** |
| 4×4 回归 | 仍全部达标（不得回退） |
| 阵列数量 | RTL 中 PE 算术核 256、Accumulator 16；无阶段副本 |

### 4.4 退出条件与决策点（P2）

- **若 P1 全部达标** → 直接进入 P4 终验，取消 P3（节省大部分预算）。
- **若 P1 只解决 II 但时序仍 > 7.300ns，或 II 无法达到 5/1** → 进入 P3，且**保留 P1 的改动 A**（它消除的是真实依赖，对后续任何形态都有益）。
- **若 P1 导致 4×4 回退** → 立即回退到 P0 冻结 commit，直接进入 P3。

## 5. P3：PE 级脉动化（根因修复）

### 5.1 目的

把"每拍组合式重建整个阵列"改成"每拍每个 PE 做一次 MAC 并把值交给邻居"，使每拍有效 MAC 从 **32–51** 提升到 **256**（8× 上限），同时消除 rolled 写回的选择器路径，让 16×16 时序与 II 一次到位。

### 5.2 修改方法（分四个子步，每步独立验收）

**P3.1：把 QK 的内层循环压成"每 PE 每拍一次 MAC"的最小循环。**

- 每个 PE 只读自己的权重/操作数寄存器与邻居来的值；
- 累加结果只写回自己的寄存器，**不经过任何共享数组**；
- 循环体只包含：读两个值 → 一次 `peMacUnit` → 写累加器 → 转发值给邻居；
- 目标：该循环 achieved II = 1、单 PE 延迟 ≤ 2 拍。

**P3.2：把阵列互联改成常数端口。**

- 由"控制器对全分区数组广播/聚集"改为**邻居转发**（行内右移、行间下移），控制器只负责边界供数与 `LOAD_SIGNAL` 式脉冲；
- 检查综合报告端口宽度，确认没有出现随 `PE_DIM` 平方增长的选择器网络。

**P3.3：权重/操作数驻留与重载。**

- 让 K tile（QK）与 V tile（PV）在多家 key tile 或多个 query tile 期间**驻留**在 PE 寄存器中，只在必要时（例如首个输出出阵列时）重载；
- 目标：把权重装载开销从关键路径与 II 中移出，同时避免复制阵列。

**P3.4：把 ROW_SUM / softmax 从主阵列分流。**

- ROW_SUM 用一条独立的窄归约通路（每列一条），PWL 仍复用阵列但不再占用其峰值并行度；
- 保持"只允许一套 PE 阵列 + 每列一条 Accumulator"的约束，分流的是**控制路径**而不是复制阵列。

### 5.3 验收目标

| 判据 | 目标 |
|---|---|
| 每拍有效 MAC | 16×16 达到 **256 MAC/cycle**（或经用户确认的口径） |
| 16×16 QK / ROW_SUM II | **5**（若结构允许则为 1，需用户确认是否放宽该目标） |
| 16×16 PWL / PV II | **1** |
| 16×16 顶层估算周期 | **≤ 7.300ns** |
| 单阵列约束 | RTL 层次/实例数显示 PE 算术核 = 256、Accumulator = 16，无阶段副本 |
| 数据 | 16×16 与 4×4 的 CSim + RTL CoSim 全部通过（0.03 容差） |
| 4×4 回归 | 全部达标 |

### 5.4 风险与回退

| 风险 | 触发信号 | 应对 |
|---|---|---|
| 脉动化后 4×4 回退 | 4×4 时序或 II 变差 | 用 `PE_DIM<=4` 分支保留原形态，16×16 才走脉动路径 |
| 工具把脉动阵列 outline 成多份 | RTL 实例数 > 256 | 改回单一调用点 + 明确的 `ALLOCATION limit=1` |
| BRAM 端口爆炸（V 转置读） | 综合报端口/II 违例 | 改 V 的读顺序或加片上转置缓冲（属数据缓冲，非阵列副本） |
| 浮点路径打不到 7.300ns | 估算 > 7.300ns | 拆流水级、给乘法/加法显式寄存；**不放宽时钟或 uncertainty** |
| 16×16 综合再次超时 | CSynth > 60 分钟 | 立即停并读层次/设计规模报告，回到 P3.1 缩小单拍体 |
