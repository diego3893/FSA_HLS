## 2 我方与 Codex 方案的对齐与差异

### 2.1 完全接受的部分

- **阶段划分**（0 固定证据 → 1 修测试 → 2 单实例证据 → 3 空间 query 分块 → 4 通信流水+floorplanning → 5 恢复 16×16）；
- **query 列分块**作为首选分法（`row=key`、`col=query`，分块后不同 query 之间**不需要跨块归约**，因此不改 FMA 顺序、不改数值）；
- **TAPA 三原则**（状态靠近使用者、优先流水化前向通信、先按逻辑局部性分块再规划位置）；
- **不预设固定跨 SLR 拍数**、**4×4 不强行跨 SLR**；
- **每个结论标注证据等级**，不用被覆盖的报告或历史 HEAD 代替本轮证据；
- **一次候选只验证一个主要假设**，前一步未达标不叠加下一步。

### 2.2 我补充的三条执行约束

1. **本地能力必须写进验收**：本机无 Vitis，`third_party/vitis_hls/include` 虽有头文件但工具链未验证。所以"阶段 1 的测试台改动"在本地**只能静态审查**（语法结构、用例覆盖、检查逻辑），其**行为正确性必须由远端 CSim 验证**。不能把"本地改完"写成"已验证"。
2. **事务数变化会改变 CoSim 时标**（Codex §6 已指出）：扩展用例后 60 分钟硬超时可能被触及。我建议在阶段 1 就把 **4×4 的事务数控制在 15 个以内**（当前 9 个），并在报告里改用**逐事务周期**而非平均 latency，避免时标不可比。
3. **测试台改动不得影响综合硬件**：新增用例必须在同一 `main`、同一顶层调用路径内，不新增第二个被测顶层、不新增文件。合入后要确认顶层资源/II/估算周期与 P3a 一致（这是"测试台没改硬件"的判据）。

### 2.3 我不同意/需要澄清的一点

Codex §2.1 把 4×4 的 `runPeArray` 记为"报告 latency3、II1；日志 Depth4"。我核对源码与日志后认为应写成**四个独立字段**：函数 latency=3、函数 Final II=1、调度 Depth=4、以及**调用者的循环 II**（QK 5 / ROW_SUM 5 / PWL 1 / PV 1）。这样后续任何一处退化都能定位到具体字段，而不是笼统说"II 变差"。

## 4 阶段 1（本包内，代码改动集中在此）：修复测试判错能力与数值合同

**对象**：`tests/stream/test_fsa_stream_split_d.cpp`（既有文件，不新增）。**近期只做 4×4/head16。**

### 4.1 具体改动（对应 Codex §6 的 6 条）

**1.1 非有限值检查（P0，最高优先）**
现状：`test_fsa_stream_split_d.cpp:177-195` 只做 `error = |actual-expected| > 0.03`。
- **NaN 会绕过**：`error` 成为 NaN 后，`error > maximum_error` 与 `error > 0.03` 恒为假 → 该坐标**既不进入误差统计也不触发失败**；
- **Inf 通常会失败**：`Inf - 有限值 = Inf > 0.03` → 会报错（但报的是"数值超差"，不是"输出非有限"，诊断信息会误导）。
改法：在逐元素比较**之前**先判 `std::isfinite(actual) && std::isfinite(expected)`；任一非有限即判失败，输出**首个性坐标、数值、以及两者的位模式**（actual 是 FP32，expected 是 **double/FP64**，两者的位模式分别按各自格式报告）。
保留 0.03 门槛不变。
**检查器自身的验证**：用**人工构造的 NaN/Inf 值**直接驱动这段比较逻辑做自检（例如对已知的非有限数组调用同一比较函数），**不向 attention 顶层注入**尚未定义验收策略的特殊输入——顶层特殊值合同（`finiteAccMax` 的 NaN 策略）仍按 1.7 条先核实、后决定。

**1.2 canary 覆盖（P0）**
现状：非法长度用例只检查 `o_memory[0]`；**有效用例的 `status` 检查已存在（L162），保留不动**。
改法：非法长度调用前把**全部** `o_memory[0..MAX_O_WORDS-1]` 填 canary，调用后**逐 word** 校验未被改写，并要求 `status==1`。非法长度用例**至少两类**：`L=0`（已有）与 `L=MAX_SEQUENCE_LENGTH+1`（新增）；两者都**复用合法大小的 Q/K/V/O 缓冲**，不为非法长度分配或打包越界输入。也检查输出有效区之外的 word 未被写。

**1.3 边界用例（P1）——按实测事务清单，不预设事务数**
新增（沿用同一 `runCase` 机制，不删原用例）：`L ∈ {3, 4, 5, 8, 9}`（即 `D-1, D, D+1, 2D, 2D+1`），**causal 与非 causal 全覆盖**；保留原 `L=1, 2, 7, 16`。

实测事务清单（4×4/head16，`PE_DIM=4`）：

| 类别 | 用例 | 个数 |
|---|---|---|
| 原有 | `single-key-first`(1)、`two-key-ones-v`(2)、`two-key-basis-v`(2)、`two-key-basis-v-last-feature`(2)、`primary-noncausal`(7)、`primary-causal`(7)、`full-tile-noncausal`(16)、`full-tile-causal`(16) | **8** |
| 新增边界 | `L=3,4,5,8,9` × causal/noncausal | **10** |
| **有效小计** | | **18** |
| 非法长度 | `L=0`、`L=MAX_SEQUENCE_LENGTH+1` | **2** |
| **合计事务** | | **20** |

- 事务数只影响 CoSim 时间，**不预设是否触及 60 分钟硬超时**（上一轮 4×4 的 CoSim 约 3 分钟，事务数增加 2 倍多的量级通常仍远低于门槛）；以实测墙钟为准，超时则按协议标未验收并交用户决定，**不得删用例规避**。
- 若实测证明需要分轮，优先保留 `D-1/D/D+1` 的双 causal 覆盖，`2D/2D+1` 移入下一轮；这属于用户可决定的预算问题。

**1.4 定向状态路径用例（P1，最关键）**
随机长度**不能**替代状态路径覆盖。新增三类定向输入：
- **online 重标定**：让后一个 key tile 产生显著更大的 max（前 tile 的小、后 tile 的大），V 取可区分值 → 检验 `alpha < 1` 时 L/O 的 rescale 是否正确；
- **零 Q/K + ones V**、**跨块位置的 basis V** → 检验 query 路由与 L/O 更新；
- **PWL 分段边界附近**与**有界负指数**输入 → 检验 8 段命中与分段间不串扰。

**1.5 事务间残留状态（P1）**
在一次 `main` 中用不同输入/长度/causal **交替**调用顶层，检查无跨事务遗留（当前依赖随机种子差异，不够直接）。

**1.6 位模式基线（P2，结构重构前必须建立）**
现状参考实现是 double 点积 + 精确 exp 的**数学参考**，只用于 0.03 算法误差验收，**不是**混合精度/PWL 的位级金标准。
改法：在**同一次官方入口**下，对固定输入取得原始 O **位模式**快照，存为测试台内的基线期望；后续结构重构逐 word 比对。且**继续保留**独立数学参考检查。两者分开报告，**不得**把两个都在 0.03 内的输出写成"位级一致"。

**1.7 特殊值策略（P2，只核实不改）**
`finiteAccMax` 用位序比较、**没有 NaN 检测**：正 NaN 可能被当成最大值。Chisel `FPCmpUnit` 也没有显式 NaN 分支。
处理：**先对照 Chisel/CMP 与算术合同确认策略**，确认后才决定是否改比较器；**不得**为了让测试通过而擅自排除既有特殊值合同。

## 5 阶段 2（本包内只做准备）：补齐单阵列证据

**输入**：阶段 1 通过后的 4×4 构建。**先检查，再决定是否改代码。**

### 5.1 必须取得的证据（远端）

1. **RTL 实例树**：全部 `runPeArray` 实例路径、每个实例内的 RawFMA 数、Accumulator 数，以及**各阶段向哪个实例发请求**；模块**类型数**与**实例数**分开统计。
2. **交叉核对**：HLS 运算符报告 + RTL 算术单元 + DSP/LUT/FF 资源 + 调度。注意（Codex §7）：PE 尾数乘法绑 DSP/latency1，FP32 尾数乘法绑 DSP/latency2，外围对齐/舍入/选择仍在 LUT/FF；FP32 单乘法可能用多个 DSP，另有 FP32 减法通路。**DSP40 不能单独倒推 16 个 PE**。
3. **辅助资源**：`reciprocalColumns` 展开的每列倒数通路、`cvtAtoE` 转换单元、减法器、PWL 前后处理——不能只数两种 FMA 而漏掉共享/复制的辅助资源。

### 5.2 两种分支

- **若确为 16 PE + 4 列 Accumulator 且各阶段共享** → 保留层级，只更正误导性注释，清理**无调用**的 `peBankMacUnit`、`stagePeArrayResult` 与无效 bank 宏；**删除前核对 `stageAccumulatorResult` 仍在使用**（它在 `runAccumulatorColumns` 里被调用，不能一并删）。
- **若发现复制** → 最小层级修正：让 PE 调用落在同一综合共享域（例如内联 QK/ROW_SUM 包装并核对自动 outline）；`ALLOCATION` 只作约束。**一次候选只改这一个原因**。
- **若最小修正不稳定** → 改为有限状态执行器：各阶段准备操作数，在**同一个静态求值位置**使用唯一阵列，结果就地更新状态；保留 QK/ROW_SUM 反馈等待与 PV 交错；**不重新接入历史同步请求/响应 task 闭环**。

### 5.3 验收

总共 **16 个 PE RawFMA + 4 条 Accumulator RawFMA**，无阶段专属副本；完整 S/P 只有一份；阶段 1 全部用例通过；QK/ROW_SUM 有效发射间隔不差于 5、PWL/PV 不差于 1；估算周期 ≤7.300 ns。若改为单一执行循环，报告其循环 II 与各阶段有效发射间隔，**不得**用插空的 II=1 掩盖阶段吞吐退化。

## 6 阶段 3–5（不在本包，需新授权）：要点与我的判断

### 6.1 阶段 3：空间 query 分块（4×4 先试 B=2，两个 4×2 块）

- **所有权**：`reg`/`score_acc`/PWL 命中标记/score mask 归 PE 所在块；每 query 的 `running_max`/`running_sum`/`history_valid`/`output_acc`/PV 上下文归该 query 列所在块；每列 Accumulator 与列内 key 归约在同块。
- **接口**：块函数只接收**本块宽度**的 Q/状态接口，**不把 `D×D` 全阵列接口复制给每个块**；K/V 需**显式广播**，缓存复制与端口开销要计入资源。
- **索引与下溢保护**：`g=b×B`，有效 query 数 `max(0, min(B, active_queries-g))`；**先判 `active_queries>g` 再做无符号减法**。
- **不得**把 `PE_DIM` 或生产 `SA_COLS` 改成 B；不能用 B 重算 attention scale、`DIM_BLOCKS`、tile 数、AXI depth、PV key 行数。
- **数值顺序**必须逐条保持（Codex §8.2 的链条）：FP32 S → FP32 max → `cvtAtoE` 到 FP16 → SUB_MAX → SCALE → 8 段 PWL 命中同一个 FP16 P → ROW_SUM/PV 消费这一份 P；PWL 扫描期间 `reg` 保持 X；`alpha` 沿 FP32 列 Accumulator 链生成，**不换成 PE 的 FP16 PWL 路径**。
- **验收**：与未分块版本数值一致；总 PE 16 / Acc 4；无完整 S/P 复制；**证明两块同时有效时的实际调度**；阶段周期与 FIFO 容量可解释。**未通过原性能门槛的分块候选不能替代已验收基线。**

### 6.2 阶段 4：通信流水 + 粗粒度 floorplanning 闭环

- 先跑**自动布局**取真实数据（关键路径、net delay、扇出、拥塞、SLR 跨越），**再**划区域；Pblock 边界与实例路径**必须来自生成物**，不在文档里臆造坐标。
- **4×4 可能体量不足**：若自动布局已紧凑、关键路径主要在 RawFMA 内部，**接受"该规模物理感知收益不明显"**，不要为制造收益强行跨 SLR。
- 插级对象：K/V 前向广播、高扇出阶段控制、块到输出汇聚。每条边记录位宽、每 tile token 数、生产/消费顺序、级数、容量、背压协议、结束条件。
- **反馈环不能任意加延迟**：需**分别**核查每阶段自身的反馈——**PV** 是 `pv_sum inter RAW distance=8 true` 与 `output_acc inter false`（全仓唯一的 `DEPENDENCE`，位于 `split_d_controller.cpp:367-368`）；**QK 与 ROW_SUM 的反馈延迟与依赖距离要各自量测**，不能沿用 PV 的 distance 8，也不能统一写成"三者都是 distance 8"。不能被现有距离覆盖时**调整局部调度，不声明假依赖**。
- **比较设计收益的四组对照**：未分块 P3a / 分块＋自动布局 / 同一分块＋floorplan 约束 / 再＋距离感知流水。固定器件、接口、时钟、输入与物理 PE/Acc 总数。
- **物理验收**：固定 100 MHz 下 route 完成、setup WNS≥0 且 TNS=0、hold WHS≥0 且 THS=0、DRC 通过；OOC 通过 / 完整集成通过 / 板测通过**分别报告**。
- 若达到时序但端到端变慢，**不得**报告为性能优化成功。

### 6.3 阶段 5：恢复 16×16（当前不执行）

进入条件：用户恢复该方向 + 4×4 功能/单实例证据完备 + 分块方法已验证或已明确失败原因。

我的建议顺序（对 Codex §10 的细化）：

1. **先测当前 P3a 形状的 16×16（零代码）**——因为它的 `runPeArray` 延迟已从 7 拍降到 3 拍，这是唯一能直接检验"延迟是否曾约束 II"的实验。**但必须同时准备它可能复发 `204-65` 的应对**（对照：256 PE 扁平形状历史上报过该告警）。
2. 复核 `PE_ARRAY_II` 与调用协议：**注意官方 Tcl 目前不接收 `PE_ARRAY_II` 环境变量**（`run_hls.tcl` 只透传 `FSA_SPLIT_D_PE_DIM`/`HEAD_DIM`/`MAX_SEQUENCE_LENGTH`），所以设一个没进 CFLAGS 的变量**不算实验**。若要用它做实验，需要改 Tcl 的 CFLAGS（这属于流程改动，需用户同意）。
3. **先解决第 5 节末尾的吞吐目标矛盾**（见下），再谈 II 指标。

6. CoSim 仍守 60 分钟硬超时与 20 分钟无进度提前停止；但**原 15–45 分钟经验来自 7 事务**，扩展用例后不适用，超时标未验收，**不能删用例规避超时**。

### 6.4 当前需要**记录**（而非现在选死）的服务率问题

Codex §2.2 指出、我复核后同意：若 16×16 的 `runPeArray` 只有**一个**物理实例，它的服务率（Final II）就同时约束所有调用者——PWL 每段调用一次、PV 每 feature 上下文调用一次，因此"QK/ROW_SUM II=5 **且** PWL/PV II=1"能否同时成立，取决于**单元服务率**与**反馈延迟/依赖距离**两组约束，需要实测而不是先验判断。

**本包的处理方式（不再要求现在三选一）**：

1. **先如实记录基线服务率**：对当前 16×16 记录 —— 单元 Final II、各阶段调用数、每次调用的有效 PE 操作数、阶段 cycles、以及 QK/ROW_SUM/PV **各自的**反馈延迟与依赖距离（见下）。这是"当前服务率"的事实描述，不含任何架构选择。
2. **再验证空间分块能否改善**：分块**不保证**块内 II=1——它只把阵列拆成互斥子块，块内仍是同一套 PE 逻辑，服务率约束依旧存在；因此分块是否改善必须由阶段 3 的实测回答。
3. **`PE_ARRAY_II` 若仍指定 5，必须单独处理**：当前它硬编码为 `PE_DIM<=4 ? 1 : 5`，且**未在 Tcl CFLAGS 中透传**（`run_hls.tcl:12-20` 只透传 `PE_DIM`/`HEAD_DIM`/`MAX_SEQUENCE_LENGTH`），所以"把宏设成别的值"目前**不构成实验**。要用它做实验必须先改 Tcl 或源码，属于需用户同意的改动。
4. **4×4 的 latency 3 不能当作 16×16 的已知延迟**：两者形状与规模不同，16×16 的延迟必须实测。

**因此本条不阻塞当前工作**：它是 16×16 方向的输入，本包只建立记录字段（第 7 节清单已含），把选择留到阶段 5 之前、拿到实测服务率之后。
