## 1. 实际主路径

入口为 `src/stream/fsa_stream.cpp::fsa_stream` → `dataflow.cpp::fsa_streaming_v2_run`。主要 actor：

```text
core controller → SA execution plan
Q request → Q DMA ┐
K request → K DMA ├→ scratchpad → input delayer → SA → output delayer → accumulator → O DMA
V request → V DMA ┘
```

三个请求进程各写一个 stream，避免单个生产者被某一路反压时阻塞其他路。Accumulator 直接拥有 RAM 与算术，不通过请求/响应环请求另一进程。保留这些已解决的死锁规避结构。

## 2. PE 当前结构与真正需要新增的部分

当前 SA 有 `pe_register[R][C]`、`pe_results[R][H][C]`、行宽 `PeWave` pipeline，算术单元内联。代码已经保存 S/N/P 于 PE 工作寄存器，不是外置整 tile P RAM，但 C++ 的状态组织尚未变成逐 PE 的状态与链路边界。

QK 从底行向顶行走 FP32 partial：底部初值 0，其余行取下邻居 FMA 结果。现有 `peMacUnit` 接受 half a/b 与 float c。因此新增 FP32 score_acc 后，最省硬件的首版是将旧 score 作为底部 c，再把全链结果直接赋回 score_acc；不用“每 d 先求零初值 partial，再额外做 FP32 add”。

这是新设计推导，尚未综合。代价是从 score 所属 PE 向链底部送种子、链顶部向所属 PE 送回结果的本地传输，以及串行 d 的依赖。02 定义带标签的邻接传输与完成门槛；不能当作零延迟组合连线。

`pe_register` 仍可 Q/S/N/X/P 复用，因为全部 d 完成前不生成 P；P 生成后不再装 Q。当前低 DSP 优势依赖 Raw FMA 共用，不能沿用旧方案中每 PE 再实例化独立 FP32 exp 或 score 加法器的默认实现。

## 3. 精度事实

- score QK 链输出 FP32；CMP 最大值保留 FP32，返回 PE 的 score 经过 `cvtAtoE` 数值转换。
- SUB_MAX、SCALE 和 PWL 路径经过 FP16 工作寄存器。PE scale 为 FP16，Accumulator 的 alpha scale 为 FP32；两者应来自同一逻辑 D。
- Raw FMA 的 half 输出转换对小于最小正规 half 的结果采用 FTZ；不能用 Python `struct.pack('e')` 的 IEEE subnormal 行为充当位级金标准。CMP 的 HLS half cast 是另一转换入口，需单独标定。
- PWL 匹配命中后才写 P。新多周期控制应保存 piece/match 状态，避免后续 piece 使用已经改成 P 的 reg 重新判断。
- 当前 finiteAccMax 假定非 NaN 数据。全 mask 的 −inf、首次有效 tile、无历史等应使用显式 valid/history 处理，避免计算 −inf−(−inf)。
- `fp32_raw_fma` 现有独立精确测试值得复用；历史 MinGW std::fma 有不匹配记录，不能未经核对将其视为位精确 oracle。

## 5. 基线已有优化及残留风险

已经有四 bundle、Q 外存缓存、双缓冲与 dataflow 供算重叠、紧凑 SRAM、PE MAC/exp 共用、逐列 Acc 算术。新增方案保留它们。
