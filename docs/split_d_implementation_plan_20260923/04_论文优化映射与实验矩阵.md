# 论文优化映射与实验矩阵

本文的实验设计属于本项目建议。TAPA-CS 的相关依据集中在 §4.5（片内模块映射和 HBM 绑定）与 §4.6（跨区域互连流水化及汇合路径延迟平衡）；§5.1 用 Vitis+F&P 区分单片物理优化与多 FPGA 扩展收益。[论文全文](https://arxiv.org/html/2311.10189v1)

单纯做 split-d 不等于已经实现论文优化。首选证明“小阵列和 PE 内状态允许更局部的放置，并与互连流水化共同改善实际布线/时序”。HBM 供数和多 engine 为第二条可选路线。本次不规划移植自动 ILP 分区器或多 FPGA 网络。

## 1. 从机制到可发表证据

| 论文对应方向 | 本项目具体动作 | 必需证据 | 不能据此声称 |
|---|---|---|---|
| §4.5 片内模块映射 | engine/其buffer/CMP/Acc局部放置；PE内score/link与MAC邻近 | routed WNS/Fmax、路由成功率、跨SLR网数量/宽度、各区LUT/FF/DSP/BRAM占用和拥塞 | 仅改变R就已完成布局优化 |
| §4.6 互连流水化 | 在实际跨区域边加入已验证的link stages；PE端点寄存器归PE；tag/valid一起传输 | 与无新增stage同布局对照，关键路径、实际吞吐、额外FF/周期，回压/数值一致 | 加pragma就必然提高吞吐 |
| §4.5 HBM绑定 | 确认真实bundle到channel映射，比较绑定/区域KV副本 | AXI实际宽度、字节、burst、有效带宽、stall与routed时序 | 四bundle自然等于四独立HBM通道 |
| 分区与通信成本的设计思想 | 多engine按query分工，区域KV缓存/分发 | 外存字节与片上广播流量分别统计，资源均衡、扩展效率 | 单FPGA实验验证了跨FPGA扩展结论 |

论文优化的物理定义见 [§4.5–4.6](https://arxiv.org/html/2311.10189v1#S4.SS5)。以下数量/阈值/实验均是本项目自定义，非论文结果。

## 2. 固定比较条件

固定器件、工具版本、10ns时钟、2.7ns uncertainty、Q/K/V/O格式、Raw FMA/PWL实现、逻辑D/L/causal、数据集seed、实际总线宽度和内存映射。记录每个构建hash。软件模型、HLS估算、RTL cycles、Vivado routed、板测分别标记，禁止混算。

D=128时不能把当前默认D=4的1498 cycles拿来计算加速比。当前源码D=R，需构造同D/BQ/BK的全高控制配置；如全高128×16过大无法实现，记录其失败阶段，并使用可实现的D32/R32或D64/R64建立等问题对照。不能伪造失败设计的Fmax。

当前BK=BQ；新split变体允许BK独立。主对照统一BQ=BK=16，避免改变softmax的KV分组带来混杂。BK不同的测试仅用于正确性或独立调参。

## 3. 两组主实验

### A：算法分块与算力预算

| 编号 | 结构 | 目的 |
|---|---|---|
| A0 | 同算术的全高R=D、BQ=BK固定、E1 | 原始全D空间展开对照；构建过大也记录失败 |
| A1 | R=16（另扫4/8/32）、D不变、E1 | split-d本身的资源/延迟交换 |
| A2 | 与A1相同，E2/4/8逐级 | 以节约资源换query并行；先独立KV读 |
| A3 | A2加共享/区域KV供数 | 分离内存复用收益 |

A1比A0慢也可能正常：时间复用使单query需更多轮；不要把“阵列变小”写成自动加速。只有测得频率提升、可部署性提升或更多engine使吞吐改善，才有对应结论。

除自然配置比较，还提供等总PE预算比较：`E×R×BQ`接近A0；同时列出CMP/Acc、buffer、额外score/link开销，不能称严格等资源。若实际LUT/BRAM不等，再补器件资源上限下的最佳可实现点。

### B：最直接对应论文的物理消融

在同一split配置、相同E和供数模式上建立：

| 编号 | 显式局部floorplan | 新增跨区link pipeline | 其余 |
|---|---|---|---|
| B0 | 否 | 否 | 基础PE操作寄存器始终保留 |
| B1 | 是 | 否 | 与B0算术、接口相同 |
| B2 | 否 | 是 | 与B0相同stage选择规则 |
| B3 | 是 | 是 | 与B1相同布局分组 |

新增stage必须确有跨区域边；如果一个小engine完全在单区域内，就选择多个engine/共享供数的跨区边，或报告该配置无可测跨区边，不强造“优化”。B0仍保留功能必需寄存器；实验关闭的是新增互连级。

每点至少保存3个可复现实现seed（工具不支持某seed控制则记录限制），报告各点成功次数与WNS/Fmax分布，不只挑最好一次。HLS估算7.300ns只是历史记录，不能作为布线后的结果替代。

Fmax的计算方式必须统一：固定约束下报告WNS；若需Fmax，另做合法时序约束扫描/工具支持的估计并声明方法，不把1/7.300ns写成板上实测频率。改变时钟目标的探索不能覆盖固定100MHz的主对照。

## 4. 吞吐与瓶颈记录

记录端到端top cycles、kernel秒数、每秒query数、有效QK/PV乘加数、输入等待/输出等待/算术busy、AXI读写字节、最大FIFO占用、额外link stage数与FF。

`time = cycles / 实际运行频率`，多engine throughput用完整L个query的总时间；不要用单个tile理想II替代top。若执行在统一100MHz，提频潜力与实际100MHz性能分别报告。

raw score/P16数值误差及mask语义一致是所有性能点的前置条件。不同precision或者改变PWL的点单独分组。

## 5. 纠正旧流量基线

以下是payload模型，不含AXI协议、burst padding、host传输、片上流量。D为4的倍数时QKV每元素2B，O4B，Nq=ceil(L/BQ)。当前stream已Q-cache：

```text
noncausal E1:
Q = 2LD
K+V = 4LD*Nq
O = 4LD
total = 6LD + 4LD*Nq
```

L4096、D128、BQ=BK16：Q1MiB、KV512MiB、O2MiB，总515MiB。旧770MiB来自“每KV重读Q”的历史路径，只保留历史标签，不能用于当前加速比。

E8、每wave的8个query tile共享一遍完整K/V，waves=32：总67MiB；每wave三个独立区域各读一份KV：195MiB（假设每区域都参与且扫描完整K/V）。该示例无tail且noncausal。E8独立KV读取仍515MiB，增加engine不自动减流量。67/195不是带宽实测，也不直接意味着7.69/2.64倍加速。

一般Dtail时使用word计数：

```text
bytes_in_row  = 8*ceil(D/4)
bytes_out_row = 8*ceil(D/2)
query bytes = L*bytes_in_row
output bytes = L*bytes_out_row
K+V bytes E1 = 2*bytes_in_row * Σ_q nkeys(q)
noncausal nkeys(q)=L
causal nkeys(q)=min(L, BK*ceil((qb+aq)/BK))
```

causal仍会读取最后部分mask tile的整有效key行，不能按严格三角pair数直接乘D。共享wave/region时，对本组有效engines的needed-key prefix取并集，即prefix最大值；各区域分别求和。附带脚本枚举检查这个公式。

片上Q需每KV重放ND片；即使外存Q不变，其SPAD读与Delayer流量会影响吞吐。K/V共享减少外存字节，却增加广播、区域buffer及回压，必须两类都测。

## 6. 资源预测的使用边界

当前报告4×4为32DSP。沿用共享RawFMA的简化结构式 `E×(R×BQ+4×BQ)` 给16×16/E1约320，E8约2560。该数仅作综合异常检查，实际额外绑定、控制、buffer、流水会改变资源；LUT/FF尤其不能忽略。

每engine新增score有效位至少32×BK×BQ，默认1KiB；Q/S/N/X/P复用reg默认512B。完整QKV双buffer约24KiB，Acc约8.06KiB（D128/R16/BQBK16），还未含各种pipeline与RAM碎片。不得沿用8FSA的17.5DSP/PE旧估计，也不得反过来只看DSP就宣称8engine可部署。

## 7. 最小可交付论文结论

优先完成B0/B1/B3，在相同split配置上说明：局部放置减少了哪些跨区域边/拥塞；新增互连级如何改变关键路径；代价增加多少FF/cycles；端到端吞吐或可布线性是否改善。若仅资源下降、时序无改善，如实报告split-d的时间/空间交换，不强贴论文优化结论。
