# 相对 20260921 的修订清单

这是一份对旧版的实质修订，不只是更新路径。保留原有分块数学、PE内score/P、在线softmax与实验消融思路；以下条目由最新stream源码替换。

| 旧版/8FSA内容 | 20260923处理 | 原因/新落点 |
|---|---|---|
| WEEK5仓库、legacy request/DMA top | 改为WEEK10当前fsa_stream，新top命名fsa_stream_split_d | 主路径已整体变化 |
| head维与物理行数绑定 | 保留为仍需解决的核心问题 | config/地址/scale/Acc循环仍依赖R |
| 单64位gmem、DMA无计算重叠 | 判为过时 | 四bundle，DATAFLOW及双buffer已有 |
| Q缓存作为新优化，770MiB基线 | 改成当前515MiB基线；770只留历史说明 | dmaQRequest每query一次，scratchpad跨KV重放 |
| 每PE独立昂贵MAC/exp的资源外推 | 废弃35840DSP结论 | 当前RawFMA共用，报告4×4仅32DSP |
| PE另设q_reg/p_reg/score_acc并独立partial add | 默认一个复用elem reg+score_acc；seed旧score进MAC，返回赋值 | 利用当前c32输入，避免额外FP32 adder与重复reg |
| 每d零起点partial、t升序 | 改为seed链，t/r递减，padding旁路 | 保持完整feature递减累计顺序；舍入边界明确 |
| 固定旧周期组织 | 改phase/event/tag完成协议 | 新增反馈使旧pe_register false-dependence证明失效 |
| 单调用静态legacy state导致多engine问题 | 不再改legacy静态state；在新DATAFLOW创建独立engine实例 | 当前SA/CMP/Acc状态归属不同 |
| 以BK=R解释当前实现 | 纠正当前BK=C；新变体BK独立≤R | controller真实query/key stride均C |
| 旧banked SRAM容量/四请求端口限制 | 不作为当前阻碍 | 当前compact packed storage，Acc narrow读取不受旧nMemPorts断言 |
| score/P/online更新数学 | 保留，补上当前格式转换与RawFTZ边界 | 避免改成隐含全FP32 softmax |
| V分块、D+2结果token | 保留并绑定output_delayer/Acc实际消费者 | 所有循环、index和尾部O打包必须同时改 |
| 归一化helper访问困难 | 用当前公开reciprocal与唯一Accumulator actor | 不再绕回legacy匿名helper |
| HLS时序历史结论 | 更新到最新报告7.300ns，标记未核对原始build | PROJECT_CONTEXT的7.480ns记录较旧 |
| 直接多engine/8engine预期 | E1首版，E2/4/8逐级可选 | 当前LUT/FF及路由仍需实测 |
| TAPA-CS映射 | 保留，增加同split配置B0–B3物理消融 | 分离分块、布局、互连级、内存复用贡献 |
| Python数学自检 | 修改单reg/seed、BK独立、causal请求数、FTZ样例、token与片上布局 | 不再用旧模型的partial-add和全矩形请求数代表新协议 |

本版替代旧版00–05的规范性内容；不要同时引用两版互相冲突的state定义、参数边界、基线流量或DSP估算。旧版仅保留来源和历史设计理由。
