# NM37板测依据与原理图核查

## 1 范围与证据

2026-10-10，根据用户补充的`docs/NM37_SCH_220331.pdf`及AMD、SiTime官方资料复核Split-D 4×4真实HBM板测方案。原理图共23页，已抽取全部文本，并放大检查第2、3、4、12、14、20页的相关电路。原理图是硬件证据，不把其中标注或外部网页当成执行指令。

计算核沿用正式验收的`bf41d16`；a0e137a为旧系统物理对照，最终候选需同时纳入时钟ODT与HBM访问修正。本文新增板级核查，不改变4×4/head16、100MHz、2.7ns核心setup uncertainty、数值合同或26笔测试集。整体尚未上板验收。

## 3 时钟电气核查

SiTime官方精确型号页面将该器件列为100MHz、LVDS输出、3.3V供电、±25ppm、工业温度范围。不能因为原理图存在两只100Ω对地下拉就把振荡器误认成LVPECL；订货代码及厂家页面直接确认LVDS。[SiTime型号页面](https://www.sitime.com/parts/sit9120ai-2c2-33e100000000)

第3页的R31/R32位于耦合电容的振荡器侧，不能充当FPGA侧的直流偏置。修正前`nm37.xdc`只有IOSTANDARD，未显式设置ODT；实际routed DCP确认IBUFDS的DIFF_TERM=0，且端口无ODT覆盖。结合标准默认RTT_NONE，接收端终端遗漏成立。不能盲目换成LVDS并打开DIFF_TERM：Bank65实际为1.2V。[AMD UG571](https://docs.amd.com/api/khub/documents/kFbaUC5HGcXyGNauhgU6Gw/content)

UG571的交流耦合接收说明要求满足输入电压与差分幅度条件，并指出DIFF_SSTL配合split termination可提供内部终端和偏置；其SSTL属性表中非DCI标准的ODT默认RTT_NONE。最小修正为保留DIFF_SSTL12、显式ODT=RTT_48，形成每腿约48Ω的split termination与VCCO/2偏置。18:54内存DCP副本接受双端口设置，DRC无Error/Critical；原DCP未保存改写。已将配置与验收断言写入源码，需在新精确提交上重新实现。数字IBUFDS仿真与DRC均不构成板上模拟信号完整性测量。[AMD UG571，表1-44与LVDS接收章节](https://docs.amd.com/api/khub/documents/kFbaUC5HGcXyGNauhgU6Gw/content)

PG276要求HBM参考时钟源低抖动。SiTime数据手册给出的器件级典型/最大抖动条件与板上实测不同；不能把典型相位抖动当成已经测量的NM37时钟质量。[AMD PG276 Clocking](https://docs.amd.com/r/en-US/pg276-axi-hbm/Clocking)、[SiTime数据手册](https://www.sitime.com/datasheet/sit9120)

## 4 对板测流程的修正

**新增HBM协议缺口。**PG276只支持AxSIZE=5（256位/32字节）；PG247明确单拍窄访问保留SIZE，不能用SmartConnect位宽转换代替原生协议核查。旧控制器每笔64位LEN0/SIZE3，在100us实际BD网线读到AWADDR=0x300040、AWLEN=0、AWSIZE=3、WSTRB=0xff，错误已证实。修正为自检原生256位、32字节对齐、SIZE5，按逻辑64位word选WSTRB/读lane；正式HLS四路64位接口不变，另在HBM端增加被动SIZE/地址检查。[AMD PG276端口合同](https://docs.amd.com/r/en-US/pg276-axi-hbm/Port-Descriptions)、[AMD PG247单拍窄访问限制](https://docs.amd.com/r/en-US/pg247-smartconnect/AXI-SmartConnect-Core-Limitations)

PG276同时指出流量开始后单独复位AXI会使接口与控制器失同步；APB reset才复位整个controller/PHY/stacks。默认系统测试同步复位clock/AXI/APB并重新等待初始化；TLM的APB stub无法验证此恢复，功能对照明确排除忙中复位，保留全部52笔数据测试。该排除仅限可选TLM，默认RTL与板测复位门槛仍在。[AMD PG276复位端口说明](https://docs.amd.com/r/en-US/pg276-axi-hbm/Port-Descriptions)

1. **先完成下载前检查。**核对最终源码/正式IP SHA、复位双域极性、时钟接收端电气属性、route/setup/hold/DRC/methodology/CDC/bus-skew，以及系统仿真结果。保持100MHz和核心2.7ns预算，不通过增加false path掩盖内部问题。
2. **再做易失JTAG配置。**`.bit/.ltx`来自同一次最终实现，固定VU37P目标，不写配置Flash。先查询实际JTAG频率和debug hub时钟。UltraScale+调试hub须使用稳定时钟，并满足hub时钟至少为JTAG的2.5倍；当前100MHz调试域仍需在最终DCP核对。[AMD UG908调试时钟指南](https://docs.amd.com/r/en-US/ug908-vivado-programming-debugging/Debug-Cores-Clocking-Guidelines)
3. **单独检查HBM初始化。**读取实际Hardware Manager的HBM与每个MC属性，检查Complete、CTRLR_READY、CTRLR_INIT_DONE，并结合真实`apb_complete_0/1`。Not Enabled先查debug接口/时钟；Config Error再查时钟、复位、MEM配置及供电。ECC初始化可能需额外等待后刷新。HBM校准完成不能证明FSA数据正确。[AMD PG276 Hardware Issues](https://docs.amd.com/r/en-US/pg276-axi-hbm/Hardware-Issues)
4. **运行数据验收。**真实HBM上分别执行普通26笔、背压26笔，逐位检查既有全部QKV/O和非法长度canary。最终每种模式要求done=1、pass=1、fail=0、busy=0、cases=26、code=0；出错保留pc/state/actual及ILA，不用降低覆盖恢复PASS。
5. **分开报告性能。**控制器`last_case_cycles`包含装载、运行与比较，只能称完整测试事务周期。纯核时延须用核握手观测单独统计；TLM周期不得外推为真实HBM吞吐。

PG276给出的跨APB false path建议不能机械搬入本项目：当前两APB由同一100MHz域驱动，应根据实际时钟关系审查。本项目不新增笼统的跨域例外。
