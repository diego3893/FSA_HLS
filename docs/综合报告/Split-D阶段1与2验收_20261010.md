## 4 完整S/P与其他存储

| 源码对象 | 4×4/head16容量 | 生命周期与用途 |
|---|---:|---|
| `pe.reg` | 16×16=256bit | QK操作数→量化S→SUB_MAX→缩放X→最终P；每阶段覆盖 |
| `pe.score_acc` | 16×32=512bit | QK完整S累加；S消费结束后复用为PWL命中结果暂存 |
| `operand_b/c` | 256/512bit | 一次共享调用的操作数，下一请求重建；不作矩阵备份 |
| `pe_result` | 16×49=784bit | FP32/FP16/命中标志的调用结果，随后消费；综合另有流水级 |
| `score_valid/probability_ready` | 各16bit | 有效位置及PWL首次命中状态，无数值S/P副本 |
| `pv_sum[8][4]` | 1024bit | 8个feature上下文的PV部分和，按key行累加，输出更新后清零 |
| `row_sum`及max/L/alpha等列向量 | 每FP32向量128bit | online softmax的归约/历史，不是完整矩阵 |
| `q_tile/k_tile/v_tile` | 各1024bit | Q/K/V操作数；RTL各8个8×16bit RAM bank |
| `output_acc/normalized` | 各2048bit | attention输出历史及归一化输出；RTL各4个16×32bit RAM bank |

源码没有独立`S[D][D]`或`P[D][D]`备份，更没有N×N矩阵；完整QK累加结束并得到max后才量化S。PWL期间X与已命中的P同驻这一套`PeState`字段，随后ROW_SUM/PV只消费最终P；`pv_sum`是feature×query维度，不能误当key×query的P副本。

**物理寄存器的实际情况：**Outline中`pe_reg_*_reg_*`为4组各16×16bit，合计1024bit。它们分别在state78捕获QK返回、state87捕获SUB_MAX、state91捕获SCALE的X、state96捕获P。Outline还有16×32bit QK返回S寄存器；PWL子模块有16×32bit `pe_score_acc_16..31_fu_*`反馈寄存器，初始化承接S字段、首次命中后暂存P，再输出转换为最终FP16 P。旧阶段寄存器可能保持旧位模式，但后续逻辑没有回读它们重建S或P的算法路径；下一key tile重走该顺序。

QK返回的第一组FP16寄存器保存末feature操作数，不等于量化S。量化循环`236_10`另有16×16bit反馈/返回寄存器，接收FP32 S并生成SUB_MAX的输入。QK子模块中16×32bit `operand_c*_fu_*`是点积反馈累加器，另有4×16bit末行Q操作数反馈；ROW_SUM子模块为4×32bit归约反馈，PV子模块为32×32bit上下文反馈。它们和父层的阶段返回值分开存在，不应将任何重复位模式都称为新增算法矩阵。全部相关寄存器声明、累加及阶段写事件均已保存。

因此允许说明用途的阶段寄存器确实存在，而且有tile大小的阶段值。不能把源码字段复用写成HLS物理寄存器复用已经实现。当前满足“无额外可回读算法S/P备份”的合同；若未来要求阶段间也仅保留256＋512bit物理状态，必须新增明确的存储资源目标并重构验证，不能把这个更强目标标记为本轮完成。

QK与PWL反馈、PV上下文、调用结果管线及控制有效位的声明/写事件已归档；RAM表列出了Q/K/V/O和常量ROM。顶层8个BRAM来自四路AXI各2个缓冲，计算层RAM报告BRAM为0。没有新增S/P RAM、FIFO或片外备份。上述bit数为对象/可辨认寄存器组容量，不是全设计FF总量；算术流水和控制还有额外FF。
