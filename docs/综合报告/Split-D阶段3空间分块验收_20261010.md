## 2 结构与协议

```text
唯一Q/K/V外存分发器
  ├─ header、所属Q原始64-bit字、相同K/V原始128-bit字对
  │    → worker<0>：4×2 PE＋2列Acc＋本地状态 → output0
  └─ header、所属Q原始64-bit字、相同K/V原始128-bit字对
       → worker<1>：4×2 PE＋2列Acc＋本地状态 → output1
                             ↓
                 唯一O汇聚器 → 既有64-bit O AXI
```

全局D、H、DIM_BLOCKS、attention scale、tile步长和四个AXI bundle不改。query列映射为`query_base+BLOCK_ID×B+col`，active数先判断再无符号减法；causal比较仍用全局query/key。块内保留B×H Q和D×H K/V缓存、D×B PE、B列max/L/history/O及8×B PV反馈。所有阶段复用对应块内PE/Acc。

分发器直接读取有效原始DMA字，K/V每个全局query/key tile各读一次再广播，未变成两块各自重读；worker使用原dma_unpack_elem解包。不存在分发器的额外Q/K/V tile。外存访问量保持原算法，AXI burst/调度形状发生变化；没有测量实际DDR带宽。

每个query tile，每块精确读取1个header、B×H/4=8个Q字、key_tiles×D×H/4=16×key_tiles个K/V字对，最后输出B×H=32个FP32。无效query块仍读取全部广播并输出占位；只有汇聚器写有效query。key_tiles是有限结束计数，没有额外终止token。

固定汇聚顺序为block0再block1，FIFO深度8无需容纳block1全部32个输出：worker只能在本query tile的全部K/V消费完成后输出。block1输出堵塞时不再需要输入；producer最终一个kv1写入之前，相应kv0已写入，block0可以独立消费和算完，再解除汇聚等待。Q先按块分发；worker0等待KV时producer仍能向已启动worker1送完有限Q，不依赖任何输出回传。无“发送请求→等待结果→继续供数”的环。外部AXI响应和内部计算正常推进是活性前提；26事务包括空块、尾tile及causal，未观察到死锁，未进行任意AXI停顿形式验证。

## 4 实例、调度与II

在顶层可达RTL实例树递归计数，不按模块类型数或总DSP倒推：

| 对象 | 物理证据 |
|---|---|
| worker | block0与block1各1个，独立FSM |
| PE | runPeArray共2个实例，每个8条mul_11ns_11ns_22，合计16 |
| Acc | runAccumulatorColumns共2个，每个2条mul_24ns_24ns_48，合计4列 |
| 倒数 | reciprocalColumns共2个，每个2个恢复除法循环模块，合计4 |
| 减法 | FP32 fsub共8个，每个2DSP |
| 总DSP | 16×1＋4×2＋8×2=40 |

倒数wrapper内部各列共享begin_reciprocal和normalize_and_round并顺序控制；保留了原有每列恢复除法路径数量，不能称为4个完整独立的倒数actor。FP32最终归一化继续复用本块Acc。

每块runPeArray位于该worker的key-loop outline中，QK/ROW_SUM helper已INLINE，未再各自复制PE。Acc位于各worker层。证据见[rtl_instance_tree.txt](../evidence/split_d_130c778_4x4_stage3/rtl_instance_tree.txt)及[hierarchy_counts.json](../evidence/split_d_130c778_4x4_stage3/hierarchy_counts.json)。

| 循环/函数 | 两块均achieved/target II | 其他 |
|---|---|---|
| QK：109_1/110_2 | 5/5 | H16，顺序feature累加 |
| ROW_SUM：162_1 | 5/5 | D4，顺序key归约 |
| PWL：295_25 | 1/1 | 8段扫描 |
| PV：364_33 | 1/1 | distance8真实反馈保留 |
| runPeArray | 1/1 | latency3 |
| runAccumulatorColumns | 1/1 | latency7 |

runQueryTile是DATAFLOW；两个worker.start分别由独立start FIFO驱动，两条FIFO都由distributeQueryTile.start_write写入，各自ap_continue=1，不依赖另一块done。每块独立连接自己的PE/Acc，K/V AXI只属于分发器。空间并行有实例和启动控制证据，不是顺序调用一个完整阵列冒充两块；官方未启用wave/profiling，未提供逐拍重叠时间线。

源码仅有每PE一个reg/score_acc，无阵列外算法S/P备份。实际RTL仍保留阶段、反馈和共享调用接口寄存器；[storage_control_audit.json](../evidence/split_d_130c778_4x4_stage3/storage_control_audit.json)记录206行匹配的状态寄存器条目。这个条目数不是PE数或逻辑状态总bit数，也不意味着物理仅一组状态。
