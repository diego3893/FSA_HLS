### 1.2 改动明细

| # | 改动 | 对应要求 |
|---|---|---|
| A | 新增 `checkCase()`：**先判有限、再比误差**。任一 actual/expected 非有限即判失败，输出首个性坐标、数值、以及 **actual 的 FP32 位模式**与 **expected 的 FP64 位模式**（数学参考是 double，故按 FP64 报告）。误差门槛 0.03 **不变** | 修复 NaN 绕过误差比较的漏报；Inf 的诊断不再误报为"数值超差" |
| B | 新增 `checkNonFiniteDetection()` **检查器自检**：用**人工注入的 NaN/Inf**直接驱动 `checkCase`，确认它确实返回失败。**不向顶层注入**特殊输入（顶层特殊值合同尚未定案） | 证明检查器有效，而不是假设它有效 |
| C | 拆出 `runCaseWithInput()`（输入构造与提交分离），使定向用例能显式构造矩阵 | 支持定向状态路径覆盖 |

| E | 新增**边界长度**用例：`D-1, D, D+1, 2D, 2D+1`，**causal 与非 causal 各一遍** | Codex §6.2 |
| F | 新增**定向用例**：`rescale-second-tile`（含 causal）、`zero-qk-ones-v`（含 causal）、`pwl-boundary`（含 causal） | Codex §6.6 |
| G | 非法长度改为 `runInvalidLengthCase()`：`L=0` 与 `L=MAX_SEQUENCE_LENGTH+1` 两类；**全部 O 内存逐 word canary 校验**（不再只查 `o_memory[0]`）；要求 `status==1`；**复用合法大小缓冲**，不为非法长度分配越界输入 | Codex §6.3、§6 末 |

### 1.3 定向用例的构造理由（可复核）

- **`RescaleSecondTile`**：q 只在 feature0 上为 1；第 0 个 key tile 的 `k[token][0]=1.0`，第 2 个 key tile 的 `k[token][0]=2.5`。于是第 2 个 tile 的 max 明显更大 → **必然触发 `alpha<1` 的 online 重标定**，而最终输出应约为 `[1,0,0,...]`。若 rescale 写错，第一个 tile 的旧 L/O 会被错误保留，输出会明显偏离。
- **`ZeroQkOnesV`**：Q/K 全 0（所有 score 相同）→ 所有 key 概率相等；V 是按 token 位置轮转的基向量（`v[token][token%HEAD_DIM]=1`）→ 检验**跨块位置的 query 路由**与均匀概率下的输出。
- **`PwlBoundary`**：`q≡1`、`k≡1.5×grid`，`grid∈{1.0,0.5,0.0,-0.5,-1.0,-1.5}`。点积 = `HEAD_DIM×(1.5×grid)`，归一化后 `(score-max)/sqrt(H)` **恰好落在 0.75 网格**上，即 PWL 自变量分数部的分段边界 `x2 = -1, -0.75, -0.5, -0.25, 0, 0.25, 0.5, 0.75` 附近 → 检验 8 段命中与分段间不串扰。
  （附带修正了我方案 §4.1 里一个错误的缩放：原式会把分数压到 ±0.001，根本到不了边界。）

## 2 本地验证结果（已执行）

### 2.1 本地编译现在**可行**（修正"本地无能力"的说法）

仓库自带 `third_party/vitis_hls/include/ap_int.h`；此前失败只是因为**缺少 `half` 库的桩**。加入 `-DHLS_NO_XIL_FPO_LIB`（启用仓库自带的 `src/stream/local_math_stubs.cpp`）后，用 MinGW g++ 13.2 可完整编译并运行。

**可复现入口**：[tools/local_split_d_check.cmd](../tools/local_split_d_check.cmd)

```bat

tools\local_split_d_check.cmd 16 128    :: 16×16/head128
```

未使用 `-DNDEBUG`；`-Wall -Wextra` 下无告警（`-Wno-unknown-pragmas -Wno-unused-parameter` 仅用于屏蔽 HLS pragma 与接口形参，与旧检查一致）。

### 2.3 自检输出是**预期**的，不是失败

运行时 stderr 会出现两段：

```
non-finite output: case=self-test-nan ... actual_bits=0x7fc00000 expected_bits=0x0
non-finite failure: case=self-test-nan first_at=[0][0]
non-finite output: case=self-test-inf ... actual_bits=0x7f800000 expected_bits=0x7ff0000000000000
non-finite failure: case=self-test-inf first_at=[0][0]
```

这是**自检故意触发检测路径**的产物：它证明检查器确实检出并报告了 NaN/Inf（含位模式），随后自检判定"已检出"→ 继续执行。**进程最终 `[PASS]` 且 exit=0**。若这些行**不出现**，反而说明检测逻辑被跳过。

## 5 已知限制与风险

1. **事务数从 9 增至 26（4×4）**，CoSim 时间会上升。上一轮 4×4 的 CoSim 约 3 分钟，按事务数比例推算通常仍远低于 60 分钟硬门槛，但**以实测为准，不预判**。
2. **本地检查用桩库**，与远端浮点/PWL 行为可能不同；本地 PASS 不构成远端 PASS 的证据。
3. **自检会打印非有限报告**：使用者需知道那两段是预期输出，判断依据是最终 `[PASS]` 与 exit code。
4. **`finiteAccMax` 的 NaN 策略仍未定案**：它的位序比较没有 NaN 检测（Chisel `FPCmpUnit` 同样没有显式 NaN 分支）。本次**只增强了"能不能发现非有限输出"**，**没有**改变任何硬件比较器，也没有断言它与 Chisel 的 NaN 语义一致。
5. **参考实现仍是 double 数学 attention**，不是混合精度/PWL 的位级金标准；两者用途不同，本次未混同。
